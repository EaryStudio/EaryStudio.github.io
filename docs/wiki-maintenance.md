# Iris’s Idle Log wiki maintenance

The official homepage remains a static English page. The wiki is generated by
Eleventy/Nunjucks, with plain JavaScript used only for search, filters and mobile
navigation. Every content route is an actual `index.html` and remains readable
without JavaScript. The first snapshot is game release **0.56**, revision
`fd02bba2d2e4e677e39a0334461c3a9d61d5f0ee`.

## Local workflow

Use Node.js 24 (minimum 22) and the committed npm lockfile:

```sh
npm ci
npm run wiki:import -- /path/to/completed-game-export
npm run verify
npm run preview
```

`npm run verify` validates the real snapshot, runs the callback and wiki tests,
builds the site, checks internal links, verifies preserved original files and writes
a size report. Full generation produces more than 18,000 pages and can take several
minutes on Windows. The importer and build hold a shared lock so their inputs cannot
change midway. If a process is killed, inspect `data/iris.operation.lock` and remove
it only after its recorded process has ended.

Use `node scripts/wiki/serve.mjs` to view an already built site on
`http://127.0.0.1:8088/iris/wiki/` without rebuilding. It binds only to loopback.

Commit the snapshot under `data/iris/` and the website code in this repository.
Game exporter/registry changes belong in their own game-repository commit.
Snapshot files are marked `-text` in `.gitattributes`: their manifest hashes require
identical bytes on Windows and the Linux deployment runner. Do not normalize the
package's line endings.
Generated HTML, indexes, dependencies and reports are ignored. CI never accesses Unity or the
private game repository. Do not edit numbers in the JSON snapshot: fix the game or
the exporter, then export/import again.

## Import and review

The importer validates every declared file hash, rejects extra files, symlinks,
unsafe paths, unsupported schema versions and missing locales, then validates all
entity relationships. It stages and verifies a complete copy before replacement.
`reports/wiki-import.json` groups additions, removals, values/relations, text and
image changes. A failed validation leaves the existing snapshot untouched.

Game IDs can be duplicated across variants; wiki IDs and URLs cannot. String-only
references that do not distinguish a variant are rejected in the game exporter.
The entity schema shipped inside a package must match the trusted schema in
`scripts/wiki/entity.schema.json`; the importer never executes an incoming schema.

The package preserves raw base fields and names. Tables show normalized inclusive
reward ranges where the game explicitly uses Min/Max. Weighted choices show
normalized item chance; independent probabilities are not required to sum to one.
Repeated encounters remain separate rolls. Source and use links are computed from
owning relationships. Expedition links include their area, encounter and resource
level context; they do not turn tower rewards into monster drops.

Item and currency pages separate Sources, Uses and other related references.
`relations.mjs` classifies reward/cost semantics, including currency-granting
effects, shop purchases, entry costs and museum submissions. A chest's contents
belong under its Uses, while pages for those contents list the chest as a Source.
Each relation section and standalone description uses the same `UI pack 1_17`
panel as shop offers. Official store/community URLs live in `siteConfig()` and
match the existing homepage links; the sidebar also exposes them on mobile.

Familiars, stealth targets and combat actions are integrated into their owning
training/stealth action pages. `organize()` requires an unambiguous action mapping
and merges their detail content and relations without editing the imported records.
Search lists the combined page once, including the former names and IDs as aliases.
Old detail/list URLs keep static forwarding pages with canonical links and an
ordinary clickable fallback. They are excluded from the sitemap. Shop offers keep
their detail URLs under the owning shop breadcrumb; the standalone offer menu and
list are replaced by the Shops entry. All four redundant sidebar/home entries are
removed across the six locales.

`presentation.mjs` projects those raw records into player-facing fields. Inactive
union members (for example a combat chance on a life-skill familiar) are omitted.
Equipment modifiers use the game formatter's `%p`, `%`, seconds and final multiplier
semantics. Recipes separate start, production and harvest; long progression tables
remain complete inside native, keyboard-accessible disclosure controls.

Category lists have 50 entries per static page with real numbered links. Their
hashed, locale-specific list indexes let JavaScript filters search the whole
category, not just the current page. If JavaScript or the index request fails,
the static entries and pagination continue to work. Clearing filters restores
the original page. Progression order is numeric for tower floors, main objectives
and museum milestones; maze names include their game difficulty label.

The initial publication excludes the unreferenced test boss and non-guide story
dialogue. The developer approved game images and actual UI sprites on 2026-10-07.
The profile allows referenced sprites under `Assets/Sprites/`; 1,356 unique cropped
images serve 2,917 entity images, with remaining image-free definitions using a
placeholder. Complete atlases are never published. Approve additional image sources
in the game profile before exporting them. Large approved sprites are bounded to 1280px and
converted to WebP; pixel icons retain their PNG bytes and transparency.

The website uses the release's Silver font, with Fusion Pixel and Unifont fallbacks
matching the game. WOFF2 files, source hashes and license notices live under
`assets/fonts/game/`. Regenerate them with `scripts/wiki/export-fonts.py RELEASE_ROOT`
using `fonttools[woff]==4.61.1`. The font shapes are unchanged. Credit to Poppy Works
is displayed in the footer; see their linked license terms. CSS ascent/descent
overrides remove Silver's excessive reserved space below ordinary text, keeping
labels centered without shifting individual controls.

Silver is preloaded. On JavaScript-enabled pages, the initial paint waits for the
font so a temporary system typeface does not flash. A failed request or eight-second
network timeout releases the page; JavaScript-disabled pages use CSS font blocking.
The loopback preview caches font files for one hour while keeping HTML/CSS fresh.
Run `tests/wiki/font-loading.cjs` with the same Playwright setup to reproduce a
3.5-second delayed font and a failed download. Game IDs remain in the package and
search index; lists and detail headings omit them, and data references show names.

`WikiWebSkin.Export(output)` exports five slices from the real GenericConfirmPopup
and inventory prefabs. Copy its five named PNGs and `sources.json` into
`assets/wiki-ui/`. `src/wiki/client/game.css` uses the Unity border widths for CSS
border-image panels, buttons, selected tabs and icon slots. Keep the atlas itself
private. The wiki includes the game skin while the official homepage keeps its
existing layout and now shares Silver typography.

## Text, guides and URLs

Supported locales: `en`, `ko`, `ja`, `es`, `zh-Hans`, `zh-Hant`. Game text comes from
the selected release StringTables. Wiki UI text lives in `i18n/wiki/`; common data
labels are in `fields.json` and `presentation.json`. Every visible field and enum
requires all six translations; missing adapters or labels fail the build. Item
types, rarity, equipment slots and maze difficulty labels come from the exported
game UI StringTables (`WikiDisplayLabels`), so they follow the release's vocabulary.
Navigation, buttons, the home introduction and data-field labels are authored wiki
copy, not quotations from the game. Match game terminology: Familiars is `소환수`
in Korean and `召喚獣` in Japanese. Localized brand
names in the UI dictionary follow the game's localized logo artwork.

The authored getting-started guide and all five editorial rule pages were removed
at the developer’s request. Their routes, home links, sitemap entries and search
results are not generated. Rule records in a validated import package are excluded
from the website presentation model, so future imports cannot restore these pages.
The imported package and its hashes remain unchanged. In-game guide dialogues are
still shown in their related skill/category pages.

Routes use registry slugs, never translated names. Language switching preserves the
current entity. `siteOrigin`, `basePath` and `wikiPath` are centralized in
`scripts/wiki/model.mjs`. `BASE_PATH=/preview/` exercises subpath URL generation;
production uses `/`. Canonicals, hreflang links and a sitemap are generated.

For an intentional deletion or move, add an entry to `data/wiki-migrations.json`:

```json
{
  "kind": "items",
  "slug": "old-stable-slug",
  "title": "Previous item name",
  "removedIn": "0.57",
  "replacement": "items:new-stable-slug"
}
```

Omit `replacement` for a deletion without a substitute. The old URL gets a static
notice page; no server redirect or SPA fallback is assumed. Imports that remove
published entities without a migration entry are rejected.

## Verification and deployment

The workflow validates pull requests. On main it uploads only `_site` and deploys a
GitHub Pages artifact. Before the first publication, review the preview, obtain the
separate publication approval required by this repository, then change Pages source
to **GitHub Actions** and push the reviewed website commit. No cross-repository token
or automatic push is used. A failed deployment leaves the previous successful site.
Rollback by redeploying the last known-good website commit.

The build explicitly preserves `index.html`, `404.html`, `css`, `assets`,
`steam-auth`, `config`, `.well-known` and `.nojekyll`. It never copies the repository
root wholesale. The checker compares existing file bytes and checks generated links.
No service worker is installed. Search indexes have content-hashed filenames.

## Skill pages and presentation images

`scripts/wiki/organization.mjs` assigns actions and passive recipes to their owning
skill and embeds the 18 skill dialogues there. The six general dialogues appear
in their relevant category (including automatic exploration under Areas and the
shared queue under Skills). New unassigned actions or dialogues stop the build.
Actions and game guides are omitted from navigation; their detail URLs remain
available. Editorial rules are excluded from the published site entirely. Search category labels come from the locale dictionary.

Offers reuse their item icon; patch notes reuse the supplied record-book icon.
Shops reuse Gold, Ducarin and Cycle Stone currency icons; Dexterity reuses Stealth.
Embedded game dialogues are collapsed by default and open with native details controls.
These presentation fallbacks do not alter the exported snapshot. Remaining icon
needs are listed in [wiki-icon-needs.md](wiki-icon-needs.md). The game brick texture
and UI sprite provenance are recorded in `assets/wiki-ui/sources.json`; wooden
buttons repeat the original six-pixel slices instead of stretching the grain.
The supplied `UI Logo3` sheet is copied unchanged; SVG viewports display its upper-left 32×32 cell
for Statistics and upper-right cell for Museum. The home hero uses an SVG viewport over
the upper 341×220 region of MainImage, so the character remains outside the crop.

## 패치할 때 실제 작업 순서

1. **게임에서 출시 데이터를 확정합니다.** 수치·에셋·번역을 반영하고 게임 변경을
   commit합니다. CSV를 편집했다면 게임 importer로 StringTable에도 반영합니다.
   위키는 CSV가 아니라 선택한 출시 버전의 StringTable을 읽습니다.
2. **출시 commit의 별도 checkout에서 내보냅니다.** 해당 checkout에 위키 Editor
   도구·schema·기존 publication registry를 포함합니다. 현재 개발 중인 main을
   이전 버전 이름으로 export하면 안 됩니다. `git rev-parse HEAD`로 commit을 확인합니다.
3. **Tools → Wiki → Prepare Release**를 엽니다. **현재 게임 버전 / HEAD 가져오기**로
   `release`와 `sourceRevision`을 채우고 출시 대상을 확인한 뒤 저장합니다.
   기존 Review Publication도 같은 창을 엽니다. `publication.json`의 기존 `wikiId`와
   `slug`, 승인 기록은 유지합니다. 초기화용 `Create056Profile()`을 다시 실행하지 않습니다.
   게임 변경을 추가 commit했다면 마지막 HEAD를 다시 지정합니다.
4. Unity의 **Tools → Wiki → Review Publication**에서 `Discover new content (pending)`을
   실행하고 신규 항목의 공개 여부를 검토합니다. 새 파생 정의가 있으면
   `Review adapter signatures and discover derived definitions`로 확인합니다.
   필드·조건·효과가 바뀌었다면 exporter adapter부터 점검하고 서명을 승인합니다.
   **출시 정보와 검토 내용 저장**으로 저장합니다. 이미 승인한 항목은 다시 선택하지 않습니다.
5. 준비 창의 **출시 소스 / 빌드 설정 사전 검사** 후 **위키 패키지 내보내기**를 실행합니다.
   **이번 실행에서 정식 게임 빌드도 함께 생성**을 선택하면 위키 export 성공 후
   활성 Android Profile / Windows Full로 게임을 빌드합니다. Development·Demo·QA는
   제외되며 일반 Unity Build 버튼의 동작은 그대로입니다. 서명·APK/AAB 설정은
   기존 프로필을 사용합니다. 매번 새 `Exports/Wiki/<버전-SHA-시간-고유번호>/`를 만듭니다.
   `manifest.json`, `entities`, `locales`,
   `schema`, `assets`가 포함된 완성 패키지만 전달합니다. 진단은 별도
   `Exports/Wiki/reports/latest.json`에서 봅니다. 실행별 JSON 보고서는 같은 reports 폴더에
   export와 빌드 상태 및 경로를 따로 기록합니다. 게임은 `Builds/WikiRelease/<실행 ID>/`에
   생성합니다. 빌드가 실패하면 패키지가 있어도 해당 출시는 성공으로 표시하지 않습니다.
   기존 Export Public Snapshot 메뉴는 계속 `current`를 사용하므로 그 메뉴를 반복할 때만
   `current.previous`를 먼저 보관해야 합니다. 게임 소스에 commit 이후 변경이 있으면
   export가 중단되므로 오류에 나온 파일을 확인합니다. 사용자 변경을 무작정 되돌리지 않습니다.
6. 웹사이트 저장소에서 아래 명령을 실행합니다. Node.js 22 이상을 사용하며,
   패키지 경로는 실제 release checkout의 경로로 바꿉니다.

   ```powershell
   Set-Location E:\Github\EaryStudio.github.io
   npm ci
   npm run wiki:import -- "E:\path\to\release-checkout\Exports\Wiki\실행-ID"
   npm run verify
   node scripts/wiki/serve.mjs
   ```

   이미 8088 preview 서버가 실행 중이면 마지막 명령은 생략하고 새로고침합니다.
   준비 창의 **웹사이트 import 명령 복사**로 실제 패키지 경로가 들어간 명령을 얻습니다.
   `npm ci`는 최초 설치나 lockfile 변경 시 필요합니다. `npm run preview`는 다시
   빌드하면서 서버를 띄우므로 verify 직후에는 위 serve 명령이 더 빠릅니다.
7. **변경 보고서와 미리보기를 확인합니다.** `reports/wiki-import.json`에는 추가·삭제·
   수치·관계·번역·이미지 변경이 구분됩니다. 새 아이템·액션·관계, 여섯 언어와
   홈/기존 인증·config 경로를 확인합니다. 삭제·URL 이동은 먼저
   `data/wiki-migrations.json`에 이전 URL 보존 기록을 작성합니다. 게임 수치와 번역은
   snapshot JSON을 손으로 고치지 않고 원천 수정 → export → import로 고칩니다.
8. **위키 문구를 별도로 검토합니다.** `i18n/wiki/`의 메뉴·설명과 새 스킬의 게임 내
   가이드 연결은 사람이 확인합니다. 게임 데이터 변경만으로 이 편집 문구가 자동
   갱신되지는 않습니다. 화면의 버전 표시는 manifest를 따릅니다. 별도 작성했던
   사용 안내·규칙 해설·시스템 페이지는 제거했으며, 이후 import에서도 게시하지 않습니다.
9. 게임 도구/registry 변경과 웹사이트 snapshot/템플릿 변경은 **각 저장소에서 별도
   commit**합니다. 게시 승인을 받은 뒤 웹사이트를 push합니다. 최초 게시는 Pages
   source를 GitHub Actions로 전환해야 하며, 이후 main push는 설정된 workflow로
   검증·빌드·배포됩니다. 현재 로컬 구현만으로 운영 사이트가 바뀌지는 않습니다.

일반적인 수치·번역 수정은 **게임 수정·commit → release 지정 → export → import →
verify·미리보기 → 승인된 게시** 순서입니다. 신규 시스템이나 데이터 구조 변경은
exporter adapter 검토가 추가로 필요합니다.

## 패치 노트

시스템 메뉴 자리에는 **패치 노트**가 표시됩니다. 0.56 snapshot에는 0.34–0.56의
23개 버전이 포함됩니다. `/iris/wiki/{locale}/patch-notes/`는 최신 버전 본문을,
`/iris/wiki/{locale}/patch-notes/{version}/`는 해당 버전 본문을 표시합니다.
버전 목록·제목·본문은 release checkout의 `PatchNotes` StringTable에서 가져옵니다.
게임의 버전 순서와 영어 fallback을 사용하며, 날짜나 해설을 임의로 추가하지 않습니다.

새 패치에서는 게임의 `PATCH_NOTES_VERSION_LIST`, `PATCH_NOTES_TITLE_FORMAT`,
`PATCH_NOTES_BODY_x_y` 번역을 갱신하고, Review Publication의 파생 정의 검토에서
새 `patch-notes:x.y`를 승인한 뒤 평소처럼 export → import → verify합니다.
위키 본문을 따로 편집하거나 CSV를 직접 가져올 필요는 없습니다.
시스템 원천 데이터는 검증된 패키지 안에 유지하지만 페이지·검색·사이트맵에서는 제외합니다.

Browser smoke checks live in `tests/wiki/browser.cjs`. Set `PLAYWRIGHT_MODULE` to an
installed Playwright module and optionally `PLAYWRIGHT_CHANNEL`; the default uses
installed Chrome. They exercise CJK search, language switching, 320px layout,
keyboard focus, 200% text size and JavaScript-disabled content. Screenshots and
machine-readable reports are written to `reports/`. Search response measurements
are generated against the complete snapshot with a 200ms budget.
`tests/wiki/browser-patch-notes.cjs` additionally checks all six patch-note bodies,
version/language navigation, removed system URLs, 320px and no-JavaScript reading.

The pinned Eleventy 3.1.6 toolchain currently reports transitive development-only
advisories in braces/sprintf-js. No dependency JavaScript is shipped to the browser.
Only repository-owned templates and Markdown enter those parsers. Do not apply
`npm audit fix --force`, which proposes an incompatible Eleventy downgrade; update
the lockfile when compatible upstream fixes exist and rerun verification.
## Presentation adapters reviewed against 0.56

The immutable `data/iris` package remains the numerical source. Website projections
in `scripts/wiki/currency-relations.mjs`, `presentation.mjs`, and `render.mjs` derive
currency sources/costs, encounter qualifiers, and readable tables without rewriting
the imported JSON or its hashes. New exports automatically refresh these projections.

When changing the corresponding game rules, also review these runtime semantics:

- `StealthResolver`: proficiency is added after Dexterity plus the skill-level bonus.
- `ShopOfferPanelUI.RebuildDucarin`: the exported daily count applies to each B/C/D
  group, not the Gold catalog; C/D require full-game access in 0.56.
- `IdlePassiveRunner`: a zero slot storage override inherits the recipe limit.
- `WritingRuntime`: assignment selects up to three eligible skills. The completion
  threshold is configuration, not the current player's remaining progress.

Gold reward rolls remain independent of weighted item selection. Sources retain
repeated rolls and their conditions; grouping document links must not sum or remove
reward occurrences. Summon relationships supply difficulty labels only, never drops.

Skill action lists generate real 50-entry pages, including `/actions/page/2/` under
the skill URL. Their JSON indexes cover all pages for filtering. Expedition times
and Cartography unlock chances appear in each action row instead of a second list.

Run `node --test tests/wiki/review-fixes.test.mjs` for these specific regressions and
`npm run verify` for the full site before publication.

## Search and browsing state

Search ranks all matches before displaying 50 at a time. The total must count every
match, including later pages. List query, category, facets, minimum level, sorting
and page are stored in URL parameters; browser Back restores that state. Search
language links preserve the query. Static HTML pagination remains available when
JavaScript or an index request is unavailable.

The shared client pager appears above and below results. Page changes focus the
result list so keyboard navigation continues into the new entries. Empty filtered
lists include an explicit message and a reset control.

Acquisition/use links group by their final destination URL. Their nested contexts
retain each roll, owner, encounter, quantity and condition separately. Equipment
references on skill pages summarize equip-level requirements and skill bonuses;
equipment detail sections retain their original layout.

Run `node --test tests/wiki/navigation-review.test.mjs` for URL-state, complete
search results, grouped reward contexts and equipment-summary regression checks.
